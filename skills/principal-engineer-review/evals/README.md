# principal-engineer-review Evals

Use these evals after meaningful changes to `principal-engineer-review`. Compare outputs with and without the skill; the skill should improve trigger precision, adaptive reviewer context building, progressive disclosure, pair-partner follow-ups, workflow adherence, validation, and principal-engineer review quality across correctness, security, data integrity, operational risk, and MVP scope.

For `next` mode, verify deterministic candidate discovery, a direct-only search before team fallback, direct-before-team ordering even when a team PR is newer, exclusion of drafts and previously reviewed PRs, fail-closed validation, and the human gate before response drafting or GitHub mutation. For dependent change programs, verify layer, cumulative, and intermediate-state review; activation and finding ownership; restack freshness; structured handoff fields; and recipient-safe drafting that does not expose private deliberation.

Use paired cases to check calibration, not just whether the reviewer finds something: approval with optional feedback versus a consequential blocker; closure after fixes versus a new serious regression; deliberate changed intent versus accidental regression; harmless verified replay versus harmful duplicate effects; safe bounded diagnostics versus unsafe enabled flags; optional evidence versus an essential safety gap. Verify readiness survives drafting and handoff without authorizing a write. These are behavioral evaluation specifications, not an automated pass result; report which cases actually ran and keep structural package validation distinct.
