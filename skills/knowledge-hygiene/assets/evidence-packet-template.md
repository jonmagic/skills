# Evidence Packet Template

## Run Profile

Record explicit targets or selection scope, author, batch size, inactivity cutoff, exclusions, persistence destination, and optional evidence sources.

## Issue

**URL:** https://github.com/OWNER/REPO/issues/NUMBER

**Repository status:** Active or archived exclusion.

**Viewer permission:** Permission reported by GitHub.

## Original Need

Describe the requested outcome in plain language.

## Primary Evidence

Summarize the body, every relevant comment, and meaningful timeline events. Explain labels, assignments, reopen events, project changes, and explicit decisions.

## What Happened Afterward

Use linked issues, pull requests, commits, releases, current code, configuration, documentation, or configured optional sources.

## Supersession Check

**Status:** `<none | partial | full | unknown>`

Identify shipped implementation and the current canonical tracker separately. For `partial`, list completed and remaining scope.

## Runtime Activation Check

**Status:** `<active | inactive | mixed | not applicable | unknown>`

When runtime state can change the disposition, list each named target and its authoritative runtime state. Include the source and observation time. Record failed or unauthorized queries for `unknown`.

## Current Truth

State what still appears true.

## Knowledge Problem

State what is completed, outdated, duplicated, abandoned, blocked, superseded, or misleading.

## Current Connections

Link the issue to current work, or state that none was found.

## Recommendation

Choose one disposition and calibrated confidence. Account explicitly for partial supersession, mixed activation, and residual scope.

## Remaining Uncertainty

State the smallest question or evidence that would change the recommendation.

## Prior Packet Comparison

State whether a prior conclusion was confirmed or changed. If no prior packet exists, say so.

## Ownership

State current ownership evidence and whether any assignment change is justified. Treat assignment separately from disposition.

## Exact Proposed Action

List every proposed mutation: comment, body edit, labels, assignment, milestone, project placement, close, reopen, or no state change. For closure, specify `completed`, `not planned`, or `duplicate`, and name the duplicate target when applicable.

## Exact Proposed Text

> Complete outgoing text.
